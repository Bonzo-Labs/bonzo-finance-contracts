Key Findings

Root Cause: Supra Provider Transition Failure

Supra confirmed: "one [provider] going down and one onboarding." The onboarding provider returned ~221× the correct STEAM/HBAR price. When both were active, their aggregate doubled to ~456×. Supra's off-chain aggregation had no sanity bounds on the feed during transition.

No Protocol Bug — The Math Worked Correctly On Wrong Input

Bonzo Finance's liquidation formula (Aave V2 fork) and SupraOracle.sol both functioned as intended. The failure was entirely upstream in Supra's data aggregation layer. The LPCM formula correctly calculated collateral seizure using the oracle price — it had no way to detect the 463× inflation.

TWAP Circuit Breaker Would Have Prevented This

A 30-minute TWAP with a 50% deviation threshold would have rejected every spike price. Even a 5× (500%) threshold would have caught the 231× L1 spikes. The correct seizure of ~595 WHBAR would have been enforced at the true ~0.034 HBAR price.
